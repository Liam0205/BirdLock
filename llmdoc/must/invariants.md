# 维护不变量与能力边界

## 原图坐标不能与输出坐标混用

分析结果用应用 EXIF 方向后的原图像素坐标描述位置，原点在左上、y 向下。输出构图锚点和水印位置才使用相对输出宽高的归一化坐标；图像库、渲染器以及 UI 还可能使用其他坐标方向。转换必须发生在明确的边界。鸟框、关键点、鸟眼、人工修正和配准位移都要能回到同一原图像素体系，不能把缩略图像素、头部 patch 像素或归一化位置直接当原图坐标。

权威实现入口：`Sources/BirdLockCore/Analysis/AnalysisModel.swift`、`Sources/BirdLockCore/IO/ImageLoader.swift`，以及 `windows/birdlock/core/analysis.py`、`windows/birdlock/core/frames.py`。模型坐标约束见 [模型契约](../reference/models.md)。

## 分析、构图、渲染是不同阶段

- 分析负责估计“鸟在哪里、鸟头多大、角度如何、测量有多可靠”。
- 构图规划负责“把鸟放在成片哪里、用多少原图、怎样处理画面边缘”。
- 渲染与导出负责应用计划、重采样、叠加和编码。

改比例、输出尺寸、跟随强度或边缘策略，不应该变成重新识别的必要条件。反过来，只调平滑或裁切不能修复跟错目标鸟的问题。见 [处理链路](../architecture/pipeline.md) 和 [双平台架构](../architecture/platforms.md)。

## 人工修正仍然参与整条轨迹求解

手动鸟眼位置应保留原图像素坐标语义。当前实现把修正作为高权重的绝对位置观测，再重解轨迹；它不是数学上的固定等式约束，也不意味着头部模板、图像 patch 和相位相关同时重跑。修改此行为时，必须一起检查状态层的保存、撤销、重新分析和规划逻辑。

不要把“强约束”写成“位置绝对不会改变”，也不要用重新识别覆盖用户修正。用户切换到另一只目标鸟时，原鸟的修正应与新目标区分处理。排除帧当前只影响输出选帧，不会自动把该帧的测量或配准 link 从分析求解中删除；删除分析缓存还会失去保存在其中的人工修正与排除记录。权威入口：Swift `TrackBuilder.swift` 与 `AppState.swift`，Python `solver.py` 与 `app/state.py`。

## 缓存不是完整的实验身份

照片缓存与分析缓存减少重复解码和推理，但不能假定所有模型、阈值、目标选择、解码尺寸变化都会自动反映在缓存键中。修改分析算法或模型契约时，检查缓存版本和失效策略；对比新旧效果时，明确使用了哪种重新分析及代理重建方式。

当前 Swift 导入身份依据照片路径、文件大小和修改时间生成；“重新分析”不等于清空已有缩略图。具体平台策略分别查看 `SourceFrame.swift`、`ProxyCache.swift`、`Analyzer.swift` 和 Python `frames.py`、`analysis.py`，不要跨平台推定格式可互读。

## 保持模型语义一致，不依赖 README 的泛称

两平台随附的 `BirdPose.json` 都描述六个关键点：喙、左右眼、头顶、左右肩。头部拟合与眼睛选择依赖这些语义，不是任意 pose 模型都能直接替换。训练工具中的 CUB 转换路径，也不能证明随附二进制模型来自该路径。

改模型需要同时核查元数据、输入预处理、输出张量布局、关键点解释与头部拟合；见 [模型契约](../reference/models.md)。

## 所有效果描述都有适用条件

- 目标追踪使用几何与运动连续性，不提供多鸟身份绝不切换的保证。
- 有可用头部模板和足够可靠的其他关键点时，才能推算被遮挡的鸟眼；失败时仍可能回退到鸟框中心。
- 相位相关精度依赖 patch、纹理、形变、遮挡与信号质量，代码里的噪声下限不是原图精度承诺。
- 鲁棒求解主要降低异常观测的影响，不等于所有误检都会被完全删除。
- 边缘平移策略有意允许鸟离开目标锁定点，以优先避免越界和贴边。
- 合成自测不是自然连拍、模型推理或 GPU 性能验证。

## 两平台能力要分别核实

macOS 与 Windows/Python 共用算法思路，但不共用执行代码。推理后端、渲染、补帧、音乐、编码和包装方式各有差异，不能把平台 A 的功能保证写到平台 B。参见 [双平台架构](../architecture/platforms.md)。

## 发布与许可边界

`LICENSE` 和 `docs/第三方许可.md`、`docs/windows/第三方许可.md` 是许可说明入口。模型与训练数据的授权须独立检查，不能仅凭仓库开源许可证推定训练数据或替换模型允许商用。

普通编辑授权不包含提交、推送、发布或破坏性清理。打包脚本会重建 `dist/` 中的产物，Windows CI 在特定触发条件下会上传 Release 资产；执行前核实这次授权的范围。见 [开发与验证](../guides/development.md)。
