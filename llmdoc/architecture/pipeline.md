# 连拍分析与稳定轨迹

## 项目解决的问题

BirdLock 把一组飞鸟连拍照片变成鸟眼尽量稳定、翅膀继续运动的短片。它不是输入任意视频的通用去抖器：核心输入是照片序列，先估计目标鸟的运动与头部几何，再生成每张照片的构图变换。

核心方法是将两种互补观测融合：

- **绝对位置**：检测和关键点告诉我们“这一帧的鸟眼在哪里”，不易长期漂移，但逐帧有噪声。
- **相对位移**：相位相关告诉我们“下一帧鸟头相对这一帧移动多少”，局部精细，但累计后可能漂移，也会受遮挡和形变影响。

头部模板连接遮挡前后的眼睛观测；鲁棒求解综合绝对和相对证据；构图阶段再决定输出画面。单独调大平滑或提升检测置信度不能替代这套分工。

## 执行链路

```text
照片导入、排序、分组、代理缓存
    ↓
全图鸟类检测 → 同一目标的逐帧跟踪
    ↓
目标鸟区域关键点 → 头部模板拟合
    ↓
绝对鸟眼估计 + 统一尺度的鸟头纹理 patch
    ↓
相邻帧相位相关 → 相对位移与不确定度
    ↓
鲁棒轨迹求解 → 位置、大小、角度与可用帧
    ↓
构图计划 → 原图渲染 → 编码导出
```

总入口分别为 `Sources/BirdLockCore/Analysis/Analyzer.swift` 和 `windows/birdlock/core/analysis.py`。输出表示和核心维护约束见 [不变量](../must/invariants.md)。

## 导入和目标选择

导入读取图像尺寸、方向和 EXIF 拍摄时间，按拍摄时间与自然文件名组织照片，估计连拍速度并分组。缺失时间、同时间戳照片、混合格式和方向旋转都值得单独验证；不能把 EXIF 完整性当输入保证。

鸟类检测不是最终锁定点。跟踪器利用鸟框重叠、预测位置、大小和运动连续性选择目标，初始选择可受用户选鸟提示影响。当前 Swift 跟踪是几何贪心策略，不是带身份嵌入的全局多目标追踪；鸟交叉、遮挡和长时间漏检仍可能跟错。手动选目标后需要重新分析，而不是只挪动输出取景框。

权威入口：Swift `IO/SourceFrame.swift`、`Analysis/TargetTracker.swift`，Python `core/frames.py`、`core/analysis.py`。

## 头部模板：遮挡时仍能利用其他部位

关键点模型给出喙、眼睛、头顶等部位的坐标和置信度。头部模型选择一侧眼睛，将喙、选定眼睛与头顶组成局部形状，对整组可靠观测做相似变换对齐，估计典型头部模板。Procrustes 拟合允许平移、旋转和统一缩放。

眼睛缺失时，只要模板已建立、其他点仍可靠，就能用剩余点摆放模板，推算眼睛位置。当前六点布局虽然还输出肩部关键点，头部拟合并不把肩部当作头部几何点。

限制：至少需要可靠观测来初始化模板；仅有喙和头顶时几何约束更弱；没有可用模板或拟合不可靠时会回退到更粗的鸟框中心。文档应称“遮挡推算”，而不是承诺“永不回退”。

权威入口：`Analysis/HeadModel.swift`、`windows/birdlock/core/head.py`；关键点语义见 [模型契约](../reference/models.md)。

## 相位相关：从纹理获取细小移动

分析阶段提取相邻帧的鸟头灰度 patch。patch 应具有统一的原图解码尺度；若每帧独立更改缩放，缩放变化会混进相位相关的平移观测。采样、图像方向和坐标变换要放在同一套约定里。

相位相关通过傅里叶域的归一化互功率谱寻找相关峰，并细化到亚像素位移。它还估计匹配质量和位置不确定度，用于轨迹求解中的权重。patch 位移须按解码尺度换算回原图像素；不能当作输出归一化锚点使用。

鸟头转动、翅膀遮挡、失焦、背景进入 patch 或纹理不足都可能破坏平移假设。低质量、缺失或不合理的匹配不能和可靠结果使用同样权重。源码里的噪声下限和 README 的合成测试数字不构成真实照片的固定精度保证。

权威入口：`Analysis/PhaseCorrelation.swift`、`IO/ImageLoader.swift`、`windows/birdlock/core/phasecorr.py` 及 `core/analysis.py`。

## 轨迹求解：不漂移，又少抖动

设第 i 帧的锁定位置为 `p_i`，关键点/模板观测为 `z_i`，相邻帧配准位移为 `d_i`。求解同时约束：

```text
p_i             尽量接近 z_i      （绝对位置约束）
p_(i+1) - p_i   尽量接近 d_i      （相对位移约束）
```

每条观测按不确定度赋权。IRLS 反复计算残差，绝对位置测量使用 Huber 权重，相对位移 link 使用 Cauchy 权重；位置的两个维度分别求解三对角系统。不要把它描述成所有异常点都被直接删除：两种鲁棒损失仍可能保留有限权重；低质量配准另在进入求解器前筛掉。

最终轨迹除了位置，还包含构图所需的头部大小、角度、方向、可用性和质量信息。缺失值补齐与平滑有各自职责，不意味着没有观测的帧获得了真实检测。

权威入口：`Analysis/TrajectorySolver.swift`、`Analysis/TrackBuilder.swift`、`windows/birdlock/core/solver.py`。

## 人工修正与重新分析

用户指定的鸟眼位置作为高权重绝对观测参与重算。它会影响邻近甚至整条轨迹，但当前不是严格固定等式；修正本身也不会自动重建模板或重新进行图像配准。排除帧和设置起止范围属于选帧/规划层，不能混同为模型识别失败。

维护时联动检查：修正的原图像素语义、保存与撤销、重新识别后的保留、无鸟帧的手动标记、UI 预览刷新和导出计划重建。

权威入口：`Sources/BirdLockApp/AppState.swift`、Swift `TrackBuilder.swift`、Python `app/state.py` 与 `core/solver.py`。

## 缓存与可复现验证

代理图像缓存和分析结果缓存是不同层。“重新分析”可能仍读取旧代理；换模型、改阈值、改目标提示或代理尺寸后，需要检查各层是否真正失效。分析中的可用帧标志也不等同于“这一帧检测到鸟”，应查看轨迹构建如何把可靠观测扩展到周围帧。

观察实际跳动时，区分检测选鸟错误、眼睛测量错误、模板推算错误、相位匹配错误、融合权重问题以及构图边缘策略；先定位阶段，再决定是否重算。合成求解与配准自测入口见 [开发与验证](../guides/development.md)。
